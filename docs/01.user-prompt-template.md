## 6. 예외 및 에러 처리 (Error Handling)
### 6.1 워크플로우 전체 실패 시 (Workflow-level Error)
- **트리거**: [Error Trigger 노드 추가]
- **에러 타입**: 
  - [ ] 타임아웃
  - [ ] API 호출 실패
  - [ ] 데이터 검증 실패
  - [ ] 기타
- **대응**:
  ```
  1. 에러 메시지 로깅
     - Slack #errors 채널로 전송
     - 포함정보: 타입, 타임스탬프, 입력 데이터 일부 (민감정보 제외)
  2. 자동 재시도 여부: [ ] Yes (횟수: 3) / [ ] No
  3. 관리자 알림: [선택, 이메일 또는 Slack]
  ```

### 6.2 특정 노드 레벨 실패 처리
| 노드명 | 실패 시나리오 | 정책 |
|--------|--------------|------|
| "고객 정보 조회 (API)" | 고객 정보 미존재 | Continue On Fail → 기본값 적용 |
| "AI 분류" | API 오류 | Retry 3회 후 실패 |
| "Slack 알림 발송" | 채널 없음 | 에러 로깅만, 워크플로우 계속 진행 |

### 6.3 논리적 예외 처리 (Fallback)
- **데이터 파싱 실패 시**: 
  - 기본값: {{ { category: '기타', priority: '보통' } }}
  - 로그: Slack #debug 채널
- **필수 필드 누락 시**:
  - 동작: 워크플로우 중단 (명확한 에러 반환)
  - 메시지: "필수 입력 필드 누락: {{ missing_fields }}"
- **외부 API 타임아웃 시** (>30초):
  - 재시도: 5초 대기 후 최대 2회
  - 최종 실패: 캐시된 응답 또는 기본값 사용

### 6.4 테스트 에러 케이스

## 7. 데이터 검증 및 테스트 (Validation & Testing)
### 7.1 입력 검증 규칙
- 이메일 형식: /^[^\s@]+@[^\s@]+\.[^\s@]+$/
- 문의 텍스트: 최소 5자, 최대 2000자
- 우선순위: enum ['normal', 'urgent']

### 7.2 출력 검증 규칙
- AI 응답 JSON 필드 모두 필수 (null 불허)
- confidence 범위: 0 ~ 1
- category는 사전에 정의된 값만

### 7.3 성공 기준
- 처리 시간: < 10초 (AI 호출 포함)
- 에러율: < 1%
- Slack 알림 발송률: 100% (실패 시 에러 알림)
