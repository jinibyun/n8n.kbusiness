# 토론토 식당 재무 자동 마감 시스템

## 개요

| 항목 | 내용 |
|---|---|
| 시나리오명 | 토론토 식당 통합 재무 자동 마감 시스템 |
| 대상 | 토론토 소재 식당 사장님 (소상공인) |
| 핵심 목표 | POS + UberEats + Stripe 매출 통합 → 순수익 자동 계산 → Slack 경영 보고 |
| 실행 주기 | 매일 밤 11:00 ET (Schedule Trigger) |
| 알림 채널 | Slack + Google Sheets (월간 누적 장부) |
| 위치 | 별도 워크플로우 |

---

## 배경 및 목적

소상공인은 데이터를 통합하는 단계에서 가장 많은 시간을 낭비합니다.
POS, 배달 플랫폼, 온라인 결제가 각각 따로 놀기 때문에 하루 마감에만 1~2시간이 소요됩니다.

이 시스템은 **매출의 '시작(결제)'부터 '마감(장부)'까지를 자동으로 연결**합니다.

> 핵심 어필:  
> "사장님, 오늘 매출은 $1,500이지만 수수료와 재료비 빼면 오늘 순수익은 $771입니다.  
> 이게 진짜 사장님 돈입니다." — 이 한 마디가 시스템 신뢰도를 결정합니다.

## 매출 데이터 소스 (3채널)

| 소스 | 파일명 패턴 | 내용 |
|---|---|---|
| **현장 POS** | `pos_YYYY_MM_DD.csv` | 당일 1행 (현금/카드/데빗 합계 + COGS) |
| **배달 (UberEats)** | `ubereats_YYYY_MM_DD.csv` | 당일 주문 건별 명세 (N행) |
| **온라인 결제 (Stripe)** | `stripe_YYYY_MM_DD.csv` | 당일 결제 건별 명세 (N행) |

### 파일 명명 규칙 및 처리 흐름

파일은 **일별로 생성** (`pos_YYYY_MM_DD.csv`). 매일 3개 파일을 폴더에 투입하면 cron이 자동 처리.

```
📁 /data/restaurant/
│
│  ← [오늘 투입 — 처리 대기]
├── pos_2026_06_14.csv
├── ubereats_2026_06_14.csv
├── stripe_2026_06_14.csv
│
│  ← [어제 처리 완료]
├── pos_2026_06_13.csv.processed
├── ubereats_2026_06_13.csv.processed
├── stripe_2026_06_13.csv.processed
│
│  ← [오류 발생한 날 — 사장님이 확인 후 수동 처리]
├── pos_2026_06_12.csv.error
│
│  ← [월간 누적 결과 — 매일 1행씩 append]
└── report_2026_06.csv
```

- **처리 완료**: 3개 파일 모두 성공 → 각각 `.csv.processed` 로 이름 변경
- **실행 조건 (strict)**: 당일 3개 파일이 **모두** 존재할 때만 처리. 하나라도 없으면 skip
- **오류 시**: 처리 실패한 파일을 `.csv.error` 로 이름 변경 → Slack 오류 알림
- **중복 방지**: `.csv` 파일만 읽기 때문에 `.processed` / `.error` 파일은 자동 skip
- **월간 결과**: `report_2026_06.csv` 에 매일 1행씩 append → 월말에 한 달치 장부 완성

### 토론토 현실 반영 포인트
- **UberEats 수수료**: 총매출의 약 **30%** — 수수료 포함 vs 제외 순수익 차이를 시각화하면 업주들이 자동화의 가치를 즉각 체감
- **Stripe 수수료**: 약 2.9% + $0.30/건
- **HST (캐나다 부가세)**: 13% — 매출에서 자동 분리 필요

## 워크플로우 설계 (3단계)

### Step 1: 데이터 소스 통합

```
[Schedule Trigger 23:00 ET]
        │
        ▼
[오늘 날짜 계산] ← YYYY_MM_DD 문자열 생성 (Code 노드)
        │
        ▼
[3개 파일 존재 확인] ← pos / ubereats / stripe 모두 있는지 체크 (Execute Command)
        │
   [IF: 3개 모두 있음?]
    ├── NO → [파일명 .csv.error 변경] → [Slack 오류 알림] → 종료
    │
    └── YES
        │
        ├─→ [pos_YYYY_MM_DD.csv 읽기]       ─── 당일 POS 1행
        ├─→ [ubereats_YYYY_MM_DD.csv 읽기]  ─── 당일 주문 건별
        └─→ [stripe_YYYY_MM_DD.csv 읽기]    ─── 당일 결제 건별
                │
        [Merge 노드] ← 3개 소스 통합
                │
        [Code 노드: 회계 계산]
                │
        ├─→ [report_YYYY_MM.csv Append]   ─── 월간 장부에 1행 추가
        ├─→ [Slack 일일 보고]
        └─→ [파일명 변경: .csv → .csv.processed] (Execute Command × 3)
```

- **날짜 자동 계산**: Code 노드로 `new Date()` → `pos_2026_06_14.csv` 형태 생성
- **Strict 체크**: 3개 중 하나라도 없으면 전체 skip, 누락 파일을 `.csv.error` 로 마킹
- **오류 처리**: `.csv.error` 파일은 Slack 알림 포함 → 사장님이 수동 확인 후 재투입
- **처리 완료**: Execute Command로 `mv` 실행 → `.csv.processed` 변경

### Step 2: 회계 로직 (Code 노드)

#### 2-1. 핵심 계산 항목

```javascript
// 매출 통합
const posSales = cash + credit + debit;
const uberNet = uberGross - uberFee;       // 수수료 차감
const stripeNet = stripeGross - stripeFee; // 수수료 차감
const totalRevenue = posSales + uberGross + stripeGross; // 총매출 (수수료 차감 전)

// HST 분리 (13%)
const netSales = totalRevenue / 1.13;      // 순매출 (세전)
const hst = totalRevenue - netSales;       // HST 금액

// 수수료 합산
const totalFees = uberFee + stripeFee;

// 원가 차감 (COGS)
const cogs = sheetsData.cogs;             // 당일 재료비 (수동 입력)
const grossProfit = netSales - totalFees; // 수수료 차감 후
const netProfit = grossProfit - cogs;     // 원가까지 차감한 순수익

// 알림 조건 판단
const uberFeeRate = uberFee / uberGross;
const stripeRatio = stripeGross / totalRevenue;
const discrepancy = Math.abs(posTotal - (bankCredit + uberSettled + stripeSettled));
```

#### 2-2. 토론토 특화 회계 항목

| 항목 | 계산 | 비고 |
|---|---|---|
| UberEats 수수료율 | `uberFee / uberGross * 100` | 30% 초과 시 경고 |
| Stripe 수수료 | `gross * 0.029 + 0.30 * count` | 건당 계산 |
| HST (13%) | `total / 1.13 * 0.13` | 연말 세금 신고용 |
| COGS (원가) | 구글 시트 수동 입력 | 당일 재료비 |
| 결제 불일치 | `POS합계 - 실입금합계` | $5 이상 시 긴급 알림 |

## 특화 기능 상세

### 기능 1: 매출원가(COGS) 자동 차감

- **구현**: 구글 시트에 '금일 재료비' 입력 칸 → 워크플로우가 자동 읽기
- **계산**: (총매출 - 결제수수료) - COGS = 진짜 순수익
- **어필**: "매출은 $1,500이지만 진짜 내 돈은 $771입니다" — 업주 열광 포인트

### 기능 2: 결제 누락(Discrepancy) 감지

- **구현**: POS 합계 vs (카드 입금 + Uber 정산 + Stripe 입금) 비교
- **알림 조건**: 차액 $5 이상 시 즉시 Slack 긴급 알림
- **메시지**: "⚠️ 경고: 결제 금액 불일치 $XX.XX 발생! 정산 확인이 필요합니다."
- **어필**: "직원 실수나 정산 누락을 사람이 찾으면 1시간, n8n은 1초"

### 기능 3: 토론토 HST(13%) 자동 분리

- **구현**: 총매출 / 1.13 = 순매출, 총매출 - 순매출 = HST
- **적재**: Google Sheets HST 컬럼에 자동 기록
- **어필**: "연말 세금 신고 시 이 데이터를 그대로 회계사에게 → 세무 비용 절감"

### 기능 4: UberEats 수수료율 경고

- **조건**: `uberFee / uberGross > 0.30`
- **메시지**: "⚠️ Uber 수수료율 30% 초과 — 매장 방문 고객 유도 전략이 필요합니다"

### 기능 5: Stripe 비중 트래킹

- **계산**: `stripeGross / totalRevenue * 100`
- **메시지**: "온라인 결제(Stripe) 비중 XX% — 예약금 결제 유도 정책 효과 분석"

### POS CSV 컬럼 (`pos_YYYY_MM.csv`)

| 컬럼명 | 타입 | 설명 |
|---|---|---|
| 날짜 | Date | YYYY-MM-DD |
| 요일 | String | 월/화/수/목/금/토/일 |
| 현금매출 | Number | Cash 결제 합계 |
| 카드매출 | Number | Credit Card 합계 |
| 데빗매출 | Number | Debit Card 합계 |
| 일매출합계 | Number | 현금+카드+데빗 |
| 재료비COGS | Number | 당일 재료비 (수동 입력) |
| 메모 | String | 특이사항 |

### UberEats CSV 컬럼 (`ubereats_YYYY_MM.csv`)

| 컬럼명 | 설명 |
|---|---|
| order_date | 주문일 (YYYY-MM-DD) |
| order_id | UberEats 주문번호 |
| items_subtotal | 수수료 차감 전 총액 |
| ubereats_commission | UberEats 수수료 (약 30%) |
| hst_collected | 고객으로부터 수집된 HST |
| net_payout | 실정산액 (subtotal - commission) |

### Stripe CSV 컬럼 (`stripe_YYYY_MM.csv`)

| 컬럼명 | 설명 |
|---|---|
| id | Stripe 결제 ID |
| created_date | 결제일 (YYYY-MM-DD) |
| amount_cad | 결제 금액 (CAD) |
| stripe_fee | Stripe 수수료 (2.9% + $0.30) |
| net_amount | 실수령액 |
| description | 결제 설명 (케이터링 예약금 등) |

## 실습 목표

1. Schedule Trigger로 매일 밤 11시 자동 실행 구성
2. Google Sheets POS 데이터 읽기 + 결제 수단별 분류
3. UberEats 수수료 자동 계산 (수수료율 30% 경고 포함)
4. Stripe API 당일 결제 데이터 수집
5. Code 노드로 HST 분리 + COGS 차감 + 순수익 계산
6. 결제 불일치($5 이상) 자동 감지 및 긴급 알림
7. Slack으로 경영 대시보드 발송
8. Google Sheets에 일별 데이터 Append → 월간 장부 자동 생성
