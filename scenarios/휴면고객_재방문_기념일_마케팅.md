# [요구사항 정의서] n8n 휴면 고객 재방문 기념일 마케팅 워크플로우

## 1. 개요

**목적**: 마지막 방문일로부터 정확히 6개월이 된 고객을 매일 자동으로 찾아, 개인화된 재방문 유도 메시지와 20% 할인 쿠폰을 자동 발송하여 휴면 고객을 활성 고객으로 전환한다.

**운영 지역**: 캐나다 토론토 (Ontario)

**배경 및 전제 조건**:
- 생일 데이터는 수집하지 않으므로 생일 마케팅은 제외하고, **마지막 방문 기념일** 중심으로 운영한다.
- 고객 데이터는 Google Sheets(이하 "고객관리 시트")에 보관되어 있으며, 데이터 양이 현재 많지 않은 초기 운영 상태이다.
- 발송 채널: **이메일(Gmail) 우선, SMS(Twilio) 보조**. 카카오 알림톡은 북미 운영 환경에 해당 없으므로 제외.
- 메시지 발송 기록은 시트에 업데이트하여 중복 발송을 방지한다.
- 메시지 언어: 고객 데이터에 언어 설정이 없으면 **영어 기본**, 한국어 고객 여부 확인 가능 시 분기 처리.

## 2. 데이터 소스 및 필수 컬럼 정의

**대상 시트**: `고객관리 (Responses)` — Google Sheets

| 컬럼명 | 예시 값 | 필수 여부 |
|---|---|---|
| 고객이름 | Jane Kim | 필수 |
| 전화번호 | +1-416-123-4567 | 우선 (Twilio SMS용, E.164 형식) |
| 이메일 | jane@email.com | 보조 (Gmail용) |
| 마지막방문일 | 2024-12-20 | 필수 |
| 방문횟수 | 3 | 선택(개인화에 활용) |
| 주요이용서비스 | Haircut, Perm | 선택(개인화에 활용) |
| 재방문유도발송여부 | Y / 공백 | 중복방지용 |
| 발송일시 | 2025-06-20 09:05 | 로깅용 |

> **Assumption**: 전화번호는 Twilio 발송을 위해 E.164 형식(+1XXXXXXXXXX)이어야 한다. 형식이 다를 경우 Code 노드에서 변환 처리.

## 3. 트리거 및 실행 조건

- **Trigger**: Schedule 노드 — **매일 오전 9:00 (Eastern Time, Toronto)** 실행 (Cron: `0 9 * * *`)
- **필터 조건**:
  - `마지막방문일`로부터 정확히 **180일(±1일 허용)** 경과한 고객
  - `재방문유도발송여부` 컬럼이 **공백(미발송)** 인 고객만 대상
  - `이메일` 또는 `전화번호` 중 하나 이상 존재하는 고객만 처리
  - `수신동의여부` = `Y` 인 고객만 처리 (CASL 준수)

## 4. 핵심 라우팅 로직

### 분기 기준: 오늘 대상 고객 수

#### 경로 A: 대상 고객 없음 (0명)
- 별도 액션 없이 실행 종료
- 슬랙 또는 이메일로 **"No dormant customers to contact today"** 요약 알림 발송 (선택)

#### 경로 B: 대상 고객 존재 (1명 이상)

각 고객에 대해 아래 순서로 처리한다.

**B-1. 개인화 메시지 생성 (AI Agent)**
- 입력 데이터: `고객이름`, `마지막방문일`, `방문횟수`, `주요이용서비스`
- AI 프롬프트 지시:
  - "Mention the customer's name and the service they last used, with a warm tone"
  - "Naturally introduce a 20% discount coupon for their next visit"
  - "Keep it short, genuine, and non-spammy (under 160 characters for SMS compatibility)"
  - "Write in English by default; switch to Korean if the customer name is Korean"
- 출력: 발송용 메시지 텍스트 1건 (이메일용 + SMS용 각각 생성)

**B-2. 발송 채널 분기 (IF 노드)**
- 조건 1: `이메일` 존재 → **Gmail 노드**로 이메일 발송 ← 기본 채널
- 조건 2: `이메일` 없고 `전화번호` 존재 → **Twilio SMS 노드**로 문자 발송 ← 보조 채널
- 조건 3: 둘 다 없음 → 스킵 처리 후 관리자에게 누락 고객 알림

**B-3. 스팸 방지 속도 조절**
- 고객 1명당 발송 간격: **최소 3초 대기** (Wait 노드)
- 일일 최대 발송 건수: **50건 제한** (초과 시 다음날로 이월)
- 발송 시간대: 오전 9:00 ~ 오후 6:00 (Eastern Time) 범위 내에서만 처리
- CASL(Canada Anti-Spam Legislation) 준수: 수신 동의(opt-in) 고객에게만 발송. 시트에 `수신동의여부` 컬럼 추가 권장.

**B-4. 발송 결과 기록 (Google Sheets Update)**
- 발송 성공 시: `재방문유도발송여부` = `Y`, `발송일시` = 현재 시각 기록
- 발송 실패 시: `재방문유도발송여부` = `FAIL`, `발송일시` = 현재 시각 기록

## 5. 에러 핸들링 및 폴백

| 오류 상황 | 처리 방식 |
|---|---|
| Google Sheets 조회 실패 | 재시도 2회 → 관리자 이메일 알림 후 종료 |
| AI 메시지 생성 실패 | 기본 템플릿 메시지로 대체 발송 |
| Gmail 발송 실패 | Twilio SMS로 자동 전환 시도 (전화번호 있는 경우) |
| Twilio SMS 발송 실패 | 실패 로그 시트에 기록 + 관리자 알림 |
| 대상 고객 50명 초과 | 당일 50건만 처리, 나머지는 익일 자동 처리 |

**기본 대체 메시지 템플릿 (AI 실패 시)**:
> "Hi {Name}, we miss you! It's been 6 months since your last visit. Come back and enjoy 20% off your next service. Use code REVISIT20. See you soon!"

## 6. 20% 할인 쿠폰 처리 방식

> **Assumption**: 쿠폰 발급 시스템이 별도로 없을 경우 아래 중 하나를 선택한다.
- **방안 A**: 고정 쿠폰 코드(`REVISIT20`)를 메시지에 포함하여 발송 ← 기본 가정
- **방안 B**: 고객 ID 기반 고유 코드 생성 (`Code 노드`에서 UUID 조합)
- **방안 C**: 예약 페이지 URL에 쿠폰 파라미터 포함 (예약 시스템 연동 시)

## 7. n8n 노드 구성 흐름 (MCP 참조용 아키텍처)

```
[Schedule Trigger - 매일 09:00 ET]
    ↓
[Google Sheets - 전체 고객 목록 조회]
    ↓
[Code/Filter 노드 - 180일 경과 & 미발송 고객 필터링]
    ↓
[IF: 대상 고객 존재 여부]
    ├─ [없음] → [종료 / 선택적 요약 알림]
    └─ [있음] → [SplitInBatches - 1건씩 순차 처리]
                    ↓
                [OpenAI - 개인화 메시지 생성 (이메일용 + SMS용)]
                    ↓
                [Wait 노드 - 3초 대기]
                    ↓
                [IF: 이메일 존재?]
                    ├─ [True]  → [Gmail 노드 - 이메일 발송]
                    └─ [False] → [IF: 전화번호 존재?]
                                    ├─ [True]  → [Twilio 노드 - SMS 발송]
                                    └─ [False] → [누락 로그 기록]
                    ↓
                [Google Sheets - 발송 결과 업데이트]
                    ↓
                [에러 발생 시 → Error Handler → 관리자 알림]
```

## 8. 관리자 알림 (일일 요약)

- **발송 시점**: 모든 건 처리 완료 후
- **채널**: 이메일 (관리자 Gmail)
- **내용 포함 항목**:
  - 오늘 대상 고객 수
  - 발송 성공 건수 (이메일 / SMS 구분)
  - 발송 실패 건수 (실패 고객명 목록)
  - 이월 처리 건수 (50건 초과 시)

## 9. 미확정 가정(Assumptions) 목록

1. 고객관리 시트의 정확한 문서 ID와 시트명 — 실제 연결 시 확정 필요
2. 전화번호 형식 — E.164(+1XXXXXXXXXX) 아닐 경우 Code 노드에서 변환 로직 추가 필요
3. 쿠폰 처리 방식 (방안 A/B/C 중 선택) — 현재 방안 A(고정 코드 REVISIT20) 기본 가정
4. 관리자 알림용 이메일 주소
5. 180일 기준의 허용 오차 범위 (±1일 vs 정확히 180일)
6. 일일 발송 한도 50건 초과 시 이월 방식 (FIFO 순서 기준 가정)
7. CASL 수신 동의 컬럼 존재 여부 — 없을 경우 시트에 `수신동의여부` 컬럼 추가 권장
8. 메시지 언어 기본값 — 영어 기본, 한국어 고객 판별 기준 미정 시 영어 단일 사용
9. Twilio 계정 SID / Auth Token / 발신 번호 — Credential placeholder로만 처리
